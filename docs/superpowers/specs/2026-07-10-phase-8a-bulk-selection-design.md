# Phase 8A – Bulk Selection & Bulk Actions
**Date:** 2026-07-10  
**Status:** Approved  
**Scope:** Selection UX, BulkActionEngine, IPC, UI components, progress, undo scaffold

---

## Goal

Universal Email Hub must let users select and act on thousands of emails in seconds, across all accounts and folders. Phase 8A builds the reusable foundation every future bulk feature (Cleanup Center, Rules Engine, Dashboard) will call into.

---

## Architecture Overview

```
selectionStore (renderer-only Zustand)
  ↓ selectedIds, isSelectionMode
ThreadItem        — hover→checkbox swap, click routing
BulkActionBar     — floating toolbar, action dispatch
  ↓ BULK_EXECUTE / BULK_CANCEL / BULK_UNDO / BULK_QUERY_IDS
IPC layer (typed channels + preload bridge)
  ↓
BulkActionEngine (main process singleton)
  ↓ batched DB writes + IMAP/Graph provider calls
DB / providers
  ↑ BULK_PROGRESS / BULK_DONE / BULK_CANCELLED events
BulkProgressToast (renderer) — live feedback + undo
```

## 1. selectionStore

**File:** `src/renderer/stores/selectionStore.ts`

Zustand store — renderer-only. Knows nothing about emails, folders, accounts, or IPC.

### State shape

```typescript
interface SelectionState {
  selectedIds: Set<string>     // thread IDs — O(1) add/remove/has
  anchorId: string | null      // last single-click target for shift-click range
}
```

### Derived values (computed at call-site or via selectors)

| Name | Formula |
|------|---------|
| `selectedCount` | `selectedIds.size` |
| `isSelectionMode` | `selectedIds.size > 0` |

### Actions

| Action | Behaviour |
|--------|-----------|
| `toggleOne(id)` | Add if absent, remove if present. Sets `anchorId = id`. |
| `selectOne(id)` | Add to set. Sets `anchorId = id`. |
| `deselectOne(id)` | Remove from set. |
| `selectRange(fromId, toId, orderedIds)` | Adds all IDs between `fromId` and `toId` (inclusive) in `orderedIds`. Does not clear existing selection. |
| `selectAll(ids)` | Replaces set with every ID in `ids`. |
| `deselectAll()` | Clears set and `anchorId`. |
| `invertSelection(allIds)` | Adds unselected, removes selected. |
| `setAnchor(id)` | Updates `anchorId` only (used after programmatic selects). |

### Invariants

- `selectionStore` never imports from `mailboxStore`, `accountStore`, or any IPC module.
- Reading selection (`mailboxStore.selectedThreadId`) is a completely separate concept. The two never interact.
- `isSelectionMode` is derived — there is no separate boolean flag to keep in sync.

## 2. BulkActionEngine

**File:** `src/main/bulk/BulkActionEngine.ts`

Singleton class owned by the main process. The renderer sends commands; the engine does all DB and provider work.

### Supported actions

```typescript
type BulkAction =
  | 'delete' | 'archive' | 'move'
  | 'markRead' | 'markUnread'
  | 'star' | 'unstar'
  | 'spam' | 'notSpam'
  | 'export' | 'copy'
```

### Request / response types

```typescript
interface BulkRequest {
  operationId: string          // UUID — generated by renderer
  action: BulkAction
  threadIds: string[]          // IDs only, never full objects
  options?: {
    targetFolderId?: string    // move, copy
    targetAccountId?: string   // copy to account
    exportFormat?: 'eml' | 'csv'
    exportPath?: string
  }
}

interface BulkProgress {
  operationId: string
  action: BulkAction
  total: number
  completed: number
  failed: number
  percentage: number           // 0–100
  currentBatch: number
  estimatedSecondsRemaining: number
  errors: string[]             // per-item error messages (capped at 20)
}

interface BulkResult {
  operationId: string
  succeeded: number
  failed: number
  errors: string[]
  undoToken?: string           // present for reversible actions
}
```

### Execution model

1. Validate: `threadIds` non-empty, `action` known, required `options` present.
2. Store `AbortController` in `Map<operationId, AbortController>`.
3. Split `threadIds` into batches of **500** (large ops) or **50** (provider-bound ops like IMAP).
4. For each batch:
   - Check `signal.aborted` — if true, emit `BULK_CANCELLED` and stop.
   - Execute DB write (transaction).
   - Execute provider sync (best-effort, non-blocking — failures accumulate in `errors`).
   - Emit `BULK_PROGRESS`.
   - `await setImmediate()` to yield the event loop.
5. On finish: emit `BULK_DONE` with `undoToken` if the action is reversible.

### Undo scaffold

Reversible actions: `archive`, `move`, `markRead`, `star`.

The engine stores a compact undo record in a `Map<undoToken, UndoRecord>` (in-memory, main process). Token format: UUID. Records expire after **30 seconds** (via `setTimeout`).

```typescript
interface UndoRecord {
  action: BulkAction
  threadIds: string[]
  // snapshot of state before the operation (enough to reverse it)
  previousFolderIds?: Record<string, string>   // threadId → folderId
  previousReadState?: Record<string, boolean>  // threadId → isRead
  previousStarState?: Record<string, boolean>  // threadId → isStarred
  createdAt: number
}
```

Full undo execution is wired but the reversal logic for each action type is implemented incrementally. `delete` and `export` carry no `undoToken`.

**Size limit:** Undo records are capped at 10,000 thread IDs. Operations larger than this still complete but return no `undoToken` (undo not offered in the toast).

### Cancellation

```
Renderer sends: BULK_CANCEL { operationId }
Engine: abortControllers.get(operationId)?.abort()
Engine emits: BULK_CANCELLED { operationId, completed, remaining }
```

### Failure handling

- Per-item failures (one message fails IMAP) accumulate in `errors[]` (capped at 20 for display). The batch continues.
- Catastrophic failures (DB unavailable) emit `BULK_DONE` with all items in `failed`.
- The renderer always receives a terminal event (`BULK_DONE` or `BULK_CANCELLED`).

## 3. IPC Channels

**Files:** `src/shared/types/ipc.ts` (types), `src/main/ipc/handlers/bulk.ts` (handlers), `src/preload/index.ts` (bridge)

### Renderer → Main (invoke)

| Channel | Payload | Returns |
|---------|---------|---------|
| `BULK_EXECUTE` | `BulkRequest` | `{ operationId }` (starts async) |
| `BULK_CANCEL` | `{ operationId: string }` | `void` |
| `BULK_UNDO` | `{ undoToken: string }` | `void` |
| `BULK_QUERY_IDS` | `BulkQueryCriteria` | `string[]` |

`BULK_QUERY_IDS` runs a DB query (same filters as `listThreads`) and returns matching IDs. The renderer feeds those into `selectionStore.selectAll(ids)`. This is how "select all unread", "select all from sender", etc. work.

### Main → Renderer (push events)

| Channel | Payload |
|---------|---------|
| `BULK_PROGRESS` | `BulkProgress` |
| `BULK_DONE` | `BulkResult` |
| `BULK_CANCELLED` | `{ operationId, completed, remaining }` |

Events are sent via `webContents.send` (same pattern as `SYNC_PROGRESS`).

### `BulkQueryCriteria`

```typescript
interface BulkQueryCriteria {
  accountId?: string
  folderId?: string
  folderType?: string
  unreadOnly?: boolean
  readOnly?: boolean
  starredOnly?: boolean
  hasAttachment?: boolean
  fromAddress?: string
  olderThanDays?: number
  newerThanDays?: number
}
```

### 4.3 BulkProgressToast

**File:** `src/renderer/components/bulk/BulkProgressToast.tsx`

```
Position:   fixed, bottom-right, z-50
            (sits above BulkActionBar when both visible)

During operation:
  "Archiving…"
  [████████░░░░] 48 / 200 (24%) — ~3s remaining
  [Cancel]

On BULK_DONE (success):
  "✓ 200 emails archived.  [Undo]"
  Auto-dismisses after 5 s. Undo button available for 30 s.

On BULK_DONE (partial failure):
  "⚠ 198 succeeded, 2 failed."
  Stays until dismissed.

On BULK_CANCELLED:
  "Cancelled. 48 of 200 completed."
  Auto-dismisses after 3 s.
```

## 5. Keyboard & Click Handling

All keyboard shortcuts are guarded against firing inside inputs, textareas, or contenteditable elements — the same pattern already used in `ThreadList.tsx:66–73`.

| Shortcut | Action |
|----------|--------|
| `Ctrl+A` | `selectAll(visibleThreadIds)` |
| `Esc` | `deselectAll()` |
| `Space` | toggle focused thread's bulk selection |
| `Delete` | if `isSelectionMode` → confirm → bulk delete |
| `Shift+Click` | `selectRange(anchorId, id, orderedVisibleIds)` |
| `Ctrl+Click` | `toggleOne(id)` — no reading-selection change |

`visibleThreadIds` and `orderedVisibleIds` are sourced from `virtualizer.getVirtualItems()` already available in `ThreadList`.
